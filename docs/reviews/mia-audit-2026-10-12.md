Auteure : Mia (UI/UX). Projet : Wá xɔ (Waxo), e-commerce FR/EN, Cotonou, mobile-first (Android entrée de gamme).

## 0. Méthode et limites (à lire d'abord)

- **Audit STATIQUE du code uniquement.** Je n'ai pas de navigateur : je n'ai vu AUCUN rendu. Tout ce qui suit est déduit de la lecture du code, des tokens (`src/app/globals.css`), des messages FR/EN, de la maquette (`docs/maquettes/*.dc.html`, lue par extraits) et de la direction Livraison Express de Vincent (`docs/design/livraison-express-2026-10-11.md`).
- KODY fait la passe navigateur réelle (375 / 768 / 1280, axe-core, clavier). La section 9 liste ce qu'il faut vérifier à l'écran en priorité.
- Contrastes : calculés depuis les tokens avec la formule WCAG (luminance relative sRGB, ratio (L1+0,05)/(L2+0,05)). Détail en section 2.
- Format des constats : `[Sévérité] · fichier:ligne · problème · impact · correctif`. Les constats à confiance limitée sont en annexe (section 10), pas dans le corps.
- Catalogue en base VIDE aujourd'hui : j'ai donc tracé chaque écran avec `products = []`.

## 2. Contrastes calculés depuis les tokens

Luminances relatives (L) : encre #141210 = 0,0062 · crème #F4F1EA = 0,8808 · blanc = 1 · `--text` #4A443C = 0,0592 · `--muted` #6B645A = 0,1298 · `--placeholder` #78716A = 0,1684 · `--terracotta` #E2552B = 0,2284 · `--terracotta-deep` #C2410C = 0,1528 · `--sun` #FFC93C = 0,6336 · `--leaf` #1F6B4A = 0,1130 · `--leaf-bg` #E5EFE7 = 0,8416 · `--border` #E2DCCF = 0,7187 · #FAF8F3 (fond des champs) = 0,9392 · #B9B1A4 = 0,4444.

Exemple de calcul (`--muted` sur crème) : canal R 107/255 = 0,4196 → ((0,4196+0,055)/1,055)^2,4 = 0,1470 ; G → 0,1274 ; B → 0,1023 ; L = 0,2126×0,1470 + 0,7152×0,1274 + 0,0722×0,1023 = 0,1298. Ratio = (0,8808+0,05)/(0,1298+0,05) = **5,18:1**.

## 3. Constats Élevés

### 3.1 Focus invisible sur fonds encre
`[Élevé]` · `src/app/globals.css:87-92` (contour `2px solid var(--ink)` pour tous les liens/boutons) appliqué sur fond encre dans : `src/components/shop/Footer.tsx:9` (classe `LINK` de tous les liens du pied de page) et `:112` (LangSwitch), `src/components/shop/LangSwitch.tsx:27-31` (ton `dark`), `src/components/shop/HomeHero.tsx:58-63` (CTA jaune « Voir le catalogue »), `:78` (« Tout voir → »), `:83-86` et `:111-115` (tuiles promo), `src/components/assistant/entries.tsx:106-112` (bouton jaune du bloc sombre du méga-menu).
- Problème : le contour encre se dessine sur un fond encre, contraste 1:1. Aucun autre indicateur au focus (seul le survol change). WCAG 2.4.7 Focus visible (AA).
- Impact : un utilisateur clavier perd sa position dans tout le pied de page (21 liens, dont CGV, WhatsApp, langue) et dans le héro, c'est-à-dire sur le CTA principal de l'accueil.
- Correctif (au token, une seule règle) : dans `globals.css`, `@layer base { .on-dark :focus-visible { outline-color: var(--sun); } }` puis ajouter `on-dark` sur les conteneurs sombres (`<footer>` du Footer, carte `bg-ink` du héro HomeHero.tsx:45, bloc MegaAssistantBlock, bloc estimation de OrderConfirmation.tsx:214, section HowItWorks). Jaune sur encre = 12,2:1. Modèle déjà correct dans le code : `CampaignBanner.tsx:136` (`focus-visible:outline-sun`).

### 3.2 La coque de la boutique reste focusable derrière le tunnel de commande
`[Élevé]` · `src/app/[lang]/(shop)/commande/page.tsx:28` (page rendue DANS le layout boutique) · `src/app/[lang]/(shop)/layout.tsx:45-74` · `src/components/checkout/CheckoutShell.tsx:23`
- Problème : le tunnel est un calque `fixed inset-0 z-50` posé au-dessus de la coque complète (lien d'évitement, bandeau, sélecteur de devise, en-tête, newsletter, pied de page). Ces éléments restent dans l'ordre de tabulation et l'arbre d'accessibilité, mais sont masqués. WCAG 2.4.11 Focus non masqué (AA, 2.2) et 2.4.3 Ordre du focus.
- Impact : en tabulant après « Confirmer la commande », le focus part dans le champ newsletter puis les liens du pied de page, invisibles ; un lecteur d'écran annonce l'en-tête et la navigation d'une page qu'on ne voit pas. Même chose sur `/commande/merci`.
- Correctif (Niveau B, structure, à valider par Kody) : sortir `commande/` et `commande/merci/` dans un groupe de routes `(checkout)` avec un layout minimal (CurrencyProvider + contenu dans `<main>`, sans Header/Footer/Newsletter/AssistantWidget). Alternative rapide : poser l'attribut `inert` sur un wrapper de la coque quand `pathname` commence par `/commande`.

### 3.3 Case à cocher CGU sans nom accessible
`[Élevé]` · `src/components/account/ui.tsx:107-120` (composant `Checkbox`) · utilisé par `src/components/account/AuthForm.tsx:190-211` (CGU, obligatoire), `:215` (newsletter), `src/components/account/AccountProfile.tsx:72`
- Problème : le `<button role="checkbox">` ne contient qu'un `<span aria-hidden>`. Le texte (« J'accepte les CGU… ») est dans un `<span>` frère non relié. Nom accessible vide. WCAG 4.1.2 Nom, rôle, valeur et 1.3.1.
- Impact : à l'inscription, un lecteur d'écran annonce « case à cocher, non cochée » sans dire quoi ; consentement CGU et opt-in newsletter non identifiables (enjeu aussi juridique : consentement « éclairé »).
- Correctif : `const id = useId()` ; `aria-labelledby={id}` sur le bouton ; `id={id}` sur le span du libellé. Lien d'erreur CGU : `aria-describedby` vers le span d'erreur (AuthForm.tsx:212).

### 3.4 Accueil avec catalogue vide
`[Élevé]` · `src/app/[lang]/(shop)/page.tsx:29-35` · `src/components/shop/HomeSections.tsx:23-44` (tuiles « 0 produit → »), `:47-79` (h2 « Catalogue », lien « Voir tout (0 produit) → », grille vide, CTA « Voir plus de produits »), `:82-104` (h2 « Nos produits les plus vendus », lien « Voir le classement complet → », grille vide) · `src/components/shop/Selection.tsx:41-98` (bandeau jaune « Notre sélection pour vous » sans aucune carte ; zone défilante vide mais focusable `tabIndex={0}` l.52-57) · `src/components/shop/MegaMenu.tsx:50` et `:97` (« 0 produit », « Tout le catalogue (0) »)
- Problème : aucune section ne teste sa liste. Le héro, lui, gère bien le vide (CTA « Voir le catalogue », note masquée, colonne promos masquée).
- Impact : la boutique EN LIGNE donne l'image d'un site cassé ou abandonné (trois titres sans contenu, compteurs à zéro), juste sous un héro qui promet la livraison le jour même. Perte de confiance immédiate ; arrêt de tabulation vide (2.4.3).
- Correctif :
  - `Selection`, `BestSellers`, `HomeCatalog` : `return null` si la liste est vide.
  - `CategoryTiles` : masquer les rayons à 0 produit ; si tous sont à 0, masquer la section.
  - `page.tsx` : si `data.products.length === 0`, insérer après le héro un bloc unique « Arrivage en cours » (fond blanc, `--radius-block`, h2 + 1 phrase + CTA newsletter ou WhatsApp + bouton assistant). Copy à demander à Marcus (emplacements : titre ≤ 6 mots, phrase ≤ 20 mots, CTA ≤ 3 mots, une ligne).
  - MegaMenu / MobileNav / puces du catalogue : ne pas afficher « (0) » ; masquer les rayons vides.

### 3.5 Catalogue vide : mauvais message et bouton inopérant
`[Élevé]` · `src/components/shop/CatalogView.tsx:143-155` · `src/components/shop/CatalogStatic.tsx:22-30` · `src/messages/fr/shop.json:153-154`
- Problème : sans aucun filtre, le catalogue vide affiche « Aucun produit ne correspond à votre recherche. » et un bouton « Effacer les filtres » qui ne fait rien (`router.replace("/catalogue")` sur `/catalogue`). La version serveur (CatalogStatic, celle que voient les moteurs et le premier affichage) n'a AUCUN état vide : « 0 produit · stock à Cotonou » au-dessus d'une grille vide. Écart maquette en plus : l'état « sans résultat » de la maquette (Waxo Boutique.dc.html:351-358) a un bouton jaune « Demander à l'assistant », absent du code.
- Impact : impasse sur la page vers laquelle pointent tous les CTA du site ; message faux (il n'y a pas de recherche).
- Correctif : deux états distincts. (a) `products.length === 0` → bloc « Arrivage en cours » (même composant que 3.4), rendu aussi dans CatalogStatic. (b) filtres sans résultat → reprendre la maquette : texte « L'assistant peut vous proposer quelque chose d'approchant dans notre stock. » + `AssistantCta` jaune + « Effacer les filtres » (bouton affiché seulement si `hasActiveFilters`).

### 3.6 Lien « rayon » du fil d'Ariane cassé
`[Élevé]` · `src/app/[lang]/(shop)/produit/[slug]/page.tsx:125` vs `src/components/shop/logic.ts:194` (`parseFilters` lit `cat`)
- Problème : le lien pointe vers `/catalogue?category=…`, paramètre ignoré : on arrive sur tout le catalogue. La maquette (l.392, `catGo`) ouvre le rayon. Si le rayon est introuvable, le lien a un texte vide (`category?.label ?? ""`) : lien sans nom, WCAG 2.4.4.
- Impact : navigation « remonter au rayon » cassée sur chaque fiche (parcours de comparaison).
- Correctif : `href={category ? \`/catalogue?cat=${encodeURIComponent(category.id)}\` : "/catalogue"}` et libellé de repli « Catalogue » (clé existante `Catalog.title`). Ajouter `aria-current="page"` sur le dernier élément (l.129).

### 3.7 Aperçu de partage WhatsApp générique sur toutes les pages
`[Élevé]` · `src/app/[lang]/layout.tsx:35` (openGraph du layout : titre = « Wá xɔ », description générique) · `src/lib/seo/metadata.ts:68-76` (`withSeo` ne pose jamais `openGraph`) · `src/app/[lang]/(shop)/produit/[slug]/page.tsx:44`
- Problème : en Next, une page qui ne définit pas `openGraph` hérite de celui du layout. Les fiches produit, packs, campagnes et le catalogue partagent donc l'og:title « Wá xɔ », la description générique et l'image OG de marque. Le helper `pageMetadata` (metadata.ts:28-55), qui le fait bien, n'est utilisé nulle part dans `src/app`.
- Impact : WhatsApp est le canal principal (direction Vincent §7). Un client qui partage une fiche envoie une vignette sans nom de produit, sans prix, sans photo.
- Correctif : dans `withSeo`, poser `openGraph: { title, description, url: canonical, type, locale, siteName }` à partir de `meta`, plus `images` optionnel. Fiche produit : `images: product.imageUrl ? [{ url: product.imageUrl }] : undefined` (sinon l'OG de marque), description tronquée à ~155 caractères. Idem `twitter`.

### 3.8 JSON-LD Product jamais posé
`[Élevé]` · `src/lib/seo/jsonld.ts:66` (`productJsonLd`) et `:94` (`breadcrumbJsonLd`) : aucun appel dans le code · `src/components/tracking/TrackingProvider.tsx:46-47` lit ce JSON-LD pour identifier la fiche
- Problème : la fiche produit n'émet ni `Product` (nom, prix XOF, disponibilité, note) ni `BreadcrumbList`.
- Impact : pas de résultats enrichis (prix, stock, étoiles) dans Google ; et le suivi qui « cherche le JSON-LD Product de la page » ne trouve rien (à signaler à Kody/Tariq : l'événement « vue produit » est probablement muet).
- Correctif : dans `produit/[slug]/page.tsx`, rendre `<JsonLd data={[productJsonLd(...), breadcrumbJsonLd([...], lang)]} />` (composant existant `src/lib/seo/JsonLdScript.tsx`). Même chose pour `packs/[slug]`. Ne pas inclure de note si `rating.count === 0`.

### 3.9 Échec de paiement en ligne : panier perdu, aucun moyen de réessayer
`[Élevé]` · `src/components/checkout/CheckoutFlow.tsx:246` (`cart.clear()` AVANT la redirection vers le paiement) · `src/components/checkout/OrderConfirmation.tsx:124-154`
- Problème : à l'échec (« Le paiement n'a pas abouti »), les seules actions sont « Nous contacter » (→ `/contact`, formulaire) et « Continuer mes achats ». Le panier est déjà vide.
- Impact : les échecs Mobile Money (délai de validation dépassé, solde) sont fréquents ; le client doit tout re-sélectionner ou écrire un formulaire. Vente perdue au moment où l'intention est maximale.
- Correctif (à arbitrer avec Kody selon l'API) : CTA principal « Réessayer le paiement » (relance sur le même numéro WX-…) ou « Payer à la livraison » pour la même commande si le paiement à la livraison est actif ; à défaut, garder un instantané des lignes dans `last-order` et proposer « Restaurer mon panier ». Remplacer « Nous contacter » par un lien WhatsApp direct `wa.me` avec le message prérempli « Commande WX-… : le paiement n'a pas abouti ».

`[Moyen]` · `src/components/admin/products/ProductsView.tsx:109-117` · `src/components/admin/shell/PageHeading.tsx:18-33` · maquette `docs/maquettes/Waxo Admin.dc.html:76-78`

  3. État vide (l.144-148), cas `data.products.length === 0` : ajouter sous la phrase un bouton « Ajouter votre premier produit » (même cible) : c'est l'état actuel de la production.

### 4.6 Bouton « Ajouter au panier · prix » sur 2 lignes en mobile
`[Moyen]` · `src/components/product/ProductBuy.tsx:58-88`
